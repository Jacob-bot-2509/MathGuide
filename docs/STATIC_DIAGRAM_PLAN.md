# MathGuide 静态图解实施方案

日期：2026-11-01
状态：方案版，未编码
关联设计：[静态图解设计](superpowers/specs/2026-11-01-static-diagrams-design.md)

## 1. 目标

把“图解”做成模型的教学动作，而不是装饰：

- 论文工作台：每篇论文一份可折叠、可缩放的思维导图，缓存复用；
- 学习区/科研主聊天：回答中按用户困惑插入临时图解，随会话保存；
- 论文工作台左栏：回答图解与聊天一起，关闭即清空；
- 2D 图可拖动/缩放；
- 3D 图可旋转/缩放；
- 不自动播放动画。点线面出现、延伸、交织属于后续动画模型。

## 2. 原则

1. 模型不生成图片、HTML、任意 SVG 或 Three.js 代码，只输出结构化图解数据。
2. 图解点由用户问题触发，模型不提前猜。
3. 图解跟着相关段落出现，不统一堆在回答末尾。
4. 图解不能阻塞正文流。
5. 图解失败只少一张图，不影响回答。
6. 论文脑图和回答图解共用渲染协议，不共用缓存与生命周期。
7. 学习区/科研区隔离不变。

## 3. 生命周期

| 类型 | 生成 | 缓存 | 保存 |
| --- | --- | --- | --- |
| 论文思维导图 | 结构生成时一次 | `doc_insights`，`docId + 内容哈希` | 随论文保存 |
| 学习区/科研主聊天回答图解 | 用户提问后，模型标记时 | 不缓存 | `ChatMsg.diagrams` 随会话保存 |
| 论文工作台左栏回答图解 | 用户提问后，模型标记时 | 不缓存 | 不保存；关闭工作台即清空 |

## 4. 触发规则

模型只在以下情况标记图解点：

- 用户明确表达“怎么理解 / 几何直观 / 关系 / 区别 / 为什么 / 步骤”等困惑；
- 回答中出现多个概念、因果链、推导步骤、几何对象或跨学科联系；
- 模型判断纯文字会显著增加理解负担。

不标记：

- 寒暄、简单事实、短答案；
- 用户没有理解困难且内容线性简单；
- 同一回答超过 2 个图解点。

兜底：

- 用户明显在问“怎么理解/几何直观”但模型没标记：回答结束后补一次图解；
- 每条回答可手动点“图解此段”。

## 5. 图解协议

### 5.1 类型

第一版：

- `tree`：论文脑图、层级结构
- `relation`：概念关系网
- `flow`：步骤、推导链、因果
- `geometry2d`：点、线、圆、多边形、向量、标注
- `plot2d`：坐标轴、函数曲线、关键点

第二版：

- `geometry3d`：点、线、向量、平面、球、立方体、圆锥、圆柱、曲线
- `surface3d`：`z=f(x,y)` 采样网格

对比型内容第一版用文字/表格，不单独做图。

### 5.2 统一结构

```json
{
  "type": "relation",
  "title": "可选标题",
  "nodes": [{"id": "a", "label": "概念", "kind": "concept"}],
  "edges": [{"from": "a", "to": "b", "label": "推出", "kind": "arrow"}],
  "shapes": [{"kind": "point", "x": 1, "y": 2, "label": "A"}],
  "annotations": [{"x": 1, "y": 2, "text": "关键点"}],
  "view": {"x": 0, "y": 0, "zoom": 1}
}
```

后端和前端共用一份 schema 校验。未知类型、未知字段、超限数据直接丢弃。

### 5.3 内联标记

模型在正文关键位置输出轻量内部标记，例如：

```text
[[MG_DIAGRAM:type=relation]]
```

用户不可见。后端：

1. 从 SSE 正文流中剥离标记；
2. 生成 `anchorId`，记录位置；
3. 启动图解规划；
4. 发送事件：

```json
{
  "mg_event": "diagram",
  "requestId": "...",
  "anchorId": "...",
  "diagram": { "...": "结构化图解" }
}
```

前端在标记位置保留占位；图到达后填入。图未到时正文继续显示，失败时移除占位。

### 5.4 规划输入

图解规划器读取：

- 本次用户问题；
- 标记前的回答正文（最多 6000 字）；
- 当前论文/知识库引用片段；
- 允许的图类型、数量上限。

规划器只输出结构化图解，不直接写数据库。

## 6. 渲染

### 6.1 2D

- SVG 渲染；
- 鼠标/触控拖动；
- 滚轮/双指缩放；
- 重置视图；
- 不自动动画；
- 主题变量与现有界面一致。

### 6.2 3D

- Three.js 静态场景；
- 拖动旋转、滚轮/双指缩放；
- 只交互时重绘，不做持续动画循环；
- DPR 上限 2；
- 切换消息/会话时释放几何体、材质、渲染器；
- 移动端可降级为固定视角 2D 投影并提示。

### 6.3 论文脑图

- 从缓存 `PaperStructure` 生成 `tree`；
- 根节点为论文标题；
- 一级节点：研究问题/方法/结论/局限/章节；
- 支持折叠、展开、拖动、缩放；
- 节点有页码锚点时点击跳回阅读器，没有则不跳；
- 打开缓存不调用模型。

## 7. 存储与限制

- `ChatMsg.diagrams?: DiagramBlock[]`；
- 学习区/科研主聊天随会话 localStorage 保存；
- 论文工作台聊天不落库，图解随聊天清空；
- 单条消息最多 2 张图；
- 单图节点 ≤40、边 ≤80、2D 形状 ≤100、3D 网格 ≤60×60；
- 图解不写入 `doc_insights`，不进入论文结构缓存；
- 删除消息/会话时图解一起删除。

## 8. 安全与降级

- schema 白名单校验；
- 文本转义，禁止 HTML/JS；
- 坐标、采样点、节点数量上限；
- 3D 不加载外部模型/贴图；
- 规划超时（12s）放弃该图；
- 渲染失败只显示文字；
- 图解事件只作用于当前消息，跨消息/跨论文不串用；
- 图解规划失败不触发外部文献检索。

## 9. 实施阶段

### P0：协议与 2D 渲染器（3–4 天）

- 新增图解 schema 与校验；
- 新增 2D SVG 渲染器：tree/relation/flow/geometry2d/plot2d；
- 拖动、缩放、重置；
- 单元测试：非法 schema、超限、空数据、渲染降级。

### P1：论文思维导图（2–3 天）

- `PaperInsights` 从嵌套列表升级为 SVG 树；
- 折叠/展开、拖动、缩放；
- 缓存读取不调用模型；
- 有页码锚点时点节点跳阅读器；
- 回归论文结构缓存与第三栏布局。

### P2：回答内联图解（5–7 天）

- 系统提示词加入图解标记规则；
- 后端剥离标记、生成锚点、启动规划；
- SSE `diagram` 事件；
- 前端占位与插入；
- `ChatMsg.diagrams` 持久化；
- 论文工作台图解不落库；
- 测试：标记剥离、正文不阻塞、图解失败、刷新恢复。

### P3：3D 图解（4–6 天）

- 引入 Three.js（懒加载，固定版本）；
- geometry3d/surface3d 渲染；
- 旋转/缩放/重置；
- 资源释放与移动端降级；
- 测试：原语渲染、上限、切换销毁。

### P4：手动与兜底（2–3 天）

- “图解此段”按钮；
- 理解型问题无标记时补图；
- 移动端触控与性能；
- 全量回归。

## 11. 验收

1. 论文脑图重复打开不调用模型；
2. 论文脑图可折叠、拖动、缩放；
3. 回答中标记位置出现图解，正文不中断；
4. 学习区/科研主聊天刷新后图解还在；
5. 论文工作台关闭后聊天与图解都清空；
6. 回答图解不出现在论文结构缓存；
7. 2D 可拖动/缩放；3D 可旋转/缩放；无自动动画；
8. 寒暄和简单回答不生成图；
9. 图解失败不影响回答；
10. 学习区/科研区隔离不变；
11. 后端测试、前端测试、类型检查、构建通过。

## 12. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 模型乱标图解点 | 触发规则 + 每题最多 2 张 + 人工“图解此段” |
| 图解幻觉 | 只从当前回答和引用片段生成；schema 白名单；不画资料外关系 |
| 正文被图解卡住 | 标记剥离 + 并行规划；规划失败只少一张图 |
| 版面跳动 | 锚点先占位，图到后原地展开；保持滚动位置 |
| 3D 依赖与性能 | 懒加载 Three.js；只交互重绘；DPR 上限；移动端降级 |
| 会话存储膨胀 | 图解数量/节点/边/网格上限；超限不生成 |
| 论文脑图与回答图混淆 | 两套存储与生命周期，只在渲染器层共用 |

## 13. 不在本版

- 自动播放点线面动画；
- 模型生成任意 SVG/HTML/Three.js 代码；
- 扫描件 OCR；
- 图解导出为独立图片；
- 论文工作台聊天持久化。
