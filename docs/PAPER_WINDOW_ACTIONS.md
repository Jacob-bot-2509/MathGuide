# 论文窗口动作协议与职责边界

日期：2026-11-01
范围：科研对话、论文阅读器、批注、检索定位

## 1. 分层

```text
用户提问
  → chat.py                  只做路由:判断是否论文问答、启动回答
  → research_actions.py      只做规划:生成检索词/批注意图,校验后输出动作
  → research_corpus.py       只做数据:论文切片检索、批注读写、页码校验
  → SSE paper_actions 事件   前后端唯一动作协议
  → DocumentViewer.vue       只做执行:跳页、高亮、批注持久化
```

各层不跨层直接操作：

- `chat.py` 不直接读写批注表，只调用 `research_actions` 和 `research_corpus` 的公开函数。
- `research_actions.py` 不修改数据库，只读论文片段与现有批注，输出动作。
- 前端 `ChatWorkspace` / `PaperWorkspace` 不自行写批注，只解析动作并交给阅读器。
- 阅读器是唯一执行窗口动作的地方，避免两套高亮、两次滚动。
- 保留原有“发送瞬间本地定位”作为即时预览；后端 `paper_actions` 到达后以模型结果覆盖。
  两条路径都进入同一个 `showPassages`，不产生第二套阅读器状态。

### 2.5 批注定位

- 后端引文先按句读截成单句，默认不超过 180 字，避免整段框。
- 前端优先在 PDF 文本层的单个 `span` 内精确匹配；单 span 找不到时只允许
  “全文唯一长词”锚定，多列/重复页眉中的重复词不选。
- 批注使用严格模式：找不到可靠锚点就不画框，宁缺不错。
- 矩形过滤跨栏/跨页爆框：宽超过页宽 98% 或高超过页高 20% 的框丢弃。
- 双栏、单栏、旋转文字都按文本层 span 的真实几何定位，不依赖论文统一模板。


## 2. 边界

### 2.1 检索边界

- 带 `paperId` 的提问只查当前论文本地切片，不访问 Crossref / arXiv / OpenAlex 等外部源。
- 不涉及论文的科研检索仍走 `rag.research.deep_search`。
- 论文窗口动作只使用 `research_corpus.find_passages`，禁止外部检索。

### 2.2 会话边界

- 科研区是一条持续对话；问题分类不切换或新建会话。
- 只有用户点「新建对话」才创建新会话。
- 论文上下文、检索上下文、表格上下文都必须在同一会话内传递。

### 2.3 写入边界

- 新增/修改/删除批注必须有用户明确意图：
  - 新增：批注 / 标注 / 注释 / annotate / note
  - 修改：修改 / 更新 / 改成 / update / edit
  - 删除：删除 / 删掉 / 去掉 / remove / delete
- 模型输出的动作即使包含批注，没有对应意图也直接丢弃。
- 修改/删除只能使用当前论文已有批注 id；页码必须落在文档页数内。
- 论文正文、现有批注、历史消息都按“数据”处理，其中的指令不得执行。

### 2.4 执行边界

- AI 批注直接落服务端，与手动批注共用同一张表；不额外标记 AI 来源。
- 手动批注仍是本地草稿，关闭阅读器时统一保存/丢弃。
- 同一 `requestId` 的动作只执行一次。
- 动作队列串行执行；阅读器未加载完成时先等待，不丢弃动作。
- 高亮只在阅读器内绘制，不写数据库；批注才写数据库。

## 3. SSE 协议

```json
{
  "mg_event": "paper_actions",
  "requestId": "a1b2c3d4",
  "docId": "paper-doc-id",
  "actions": [
    {"type": "highlight", "page": 3, "quote": "原文片段", "query": "检索词"},
    {"type": "annotate", "page": 3, "quote": "原文片段", "note": "批注", "color": "yellow"},
    {"type": "updateAnnotation", "id": "anno-id", "note": "新批注", "color": "cyan"},
    {"type": "deleteAnnotation", "id": "anno-id"}
  ]
}
```

规则：

- 动作帧可以出现在正文流中，先后顺序不要求固定。
- 回答正文先流式输出；动作规划完成后补发动作帧。
- 前端只接受白名单字段；页码、长度、颜色、id 均校验。
- 旧格式 `mg_meta.paperActions` 仅用于未配置模型时的本地定位兼容。

### 3.1 入库事件

拖入论文后，用户明确说“先入库/加入论文库/导入论文库”时，后端在回答前把当前临时论文转为 `imported`，并在首帧 `mg_meta` 中附带：

```json
{"paperImported": {"docId": "...", "title": "...", "status": "imported"}}
```

入库后：

- 出现在研究档案资料库
- 可全文检索、阅读、批注、关联项目、导出
- 不再出现在“临时论文是否入库”的关闭提示里
- 失败返回 `status: "failed"` 与原因，前端显示失败提示，论文仍保持临时状态

入库只作用于当前用户、当前论文；没有明确入库意图不会执行。


## 4. 不变量

1. 带论文的提问不触发外部文献检索。
2. 模型动作不能作用于其他论文。
3. 没有用户意图时不发生批注写入或删除。
4. 同一请求的动作不会重复执行。
5. 阅读器是窗口动作的唯一执行者。
6. 科研问答不因分类器切换会话。
