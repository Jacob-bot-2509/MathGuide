# MathGuide 静态图解设计

日期：2026-11-01
状态：方向已确认，实施方案见 `docs/STATIC_DIAGRAM_PLAN.md`
范围：论文思维导图 + 回答内联图解 + 2D/3D 渲染

## 1. 目标

让模型像灵活教学的老师一样，在用户提出理解困惑后，选择合适形式把关键概念与联系画出来：

- 论文思维导图：每篇论文一份，缓存，重复打开；
- 回答图解：按当次问题临时生成，跟着相关段落出现，随会话保存；
- 2D 支持拖动/缩放；3D 支持旋转/缩放；
- 不自动播放动画。点线面出现、延伸、交织属于后续动画模型，不在本版。

## 2. 非目标

- 不生成图片、HTML、任意 SVG 或 Three.js 代码；
- 不让回答图解进入论文结构缓存；
- 不自动给每条回答配图；
- 不在本版做自动动画；
- 不做扫描件 OCR；
- 不把图解导出为独立图片文件（后续可加）。

## 3. 当前状态

- 论文工作台第三栏已有 `PaperStructure`（问题/方法/结论/局限/大纲），按内容哈希缓存；
- `PaperInsights.vue` 的“思维导图”是嵌套列表，不是真正可折叠/缩放/连线的图；
- `GraphView.vue` 已有 SVG 布局、拖拽、缩放基础；
- 聊天 `MathText` 只支持 Markdown/LaTeX，没有图解协议；
- 论文窗口动作已有 `paper_actions` SSE 事件，可作为图解事件的协议参照。

## 4. 生命周期

| 类型 | 生成 | 缓存 | 保存 | 删除 |
| --- | --- | --- | --- | --- |
| 论文思维导图 | 结构生成时一次 | `doc_insights`，按 `docId + 内容哈希` | 随论文保存 | 论文/结构删除时 |
| 学习区/科研主聊天回答图解 | 用户提问后，模型标记时 | 不缓存 | 作为 `ChatMsg.diagrams` 随会话本地保存 | 删除消息/会话时 |
| 论文工作台左栏回答图解 | 用户提问后，模型标记时 | 不缓存 | **不保存** | 关闭工作台即清空 |

两者共用渲染协议，但不共用存储。
论文工作台“关闭即清空聊天记录”的既有规则不变，图解随聊天一起清空。

## 5. 方案选择

### A. 回答后补图

正文先完成，再生成图解。稳定，但图出现太晚，教学节奏弱。

### B. 边答边图（采用）

模型在解释到关键点时输出轻量内部标记；后端剥离标记并启动图解规划，正文继续输出；规划完成后把图解插到标记位置。

- 模型不提前猜用户需要什么图；
- 只在用户提出具体困惑、解释到相关点时标记；
- 不阻塞正文；
- 规划失败时只少一张图，不影响回答。

### C. 正文内直接输出图解 JSON

不采用。会卡流、可能泄漏 JSON、格式错误会破坏整段回答。

## 6. 触发规则

模型只在以下情况标记图解点：

1. 用户明确表达“怎么理解 / 几何直观 / 关系 / 区别 / 为什么 / 步骤”等困惑；
2. 回答中出现多个概念、因果关系、推导链、几何对象或跨学科联系；
3. 模型判断纯文字会显著增加理解负担。

不标记：

- 寒暄、简单事实、短答案；
- 用户没有理解困难且内容本身线性简单；
- 同一回答超过 2 个图解点。

兜底：

- 用户问题明显是“怎么理解/几何直观”但没有标记：回答结束后补一次图解；
- 每条回答可手动点“图解此段”。

## 7. 图解协议

### 7.1 类型

- `tree`：论文脑图、层级结构；
- `relation`：概念关系网；
- `flow`：步骤、推导链、因果；
- `geometry2d`：点、线、圆、多边形、向量、标注；
- `plot2d`：坐标轴、函数曲线、关键点；
- `geometry3d`：点、线、向量、平面、球、立方体、圆锥、圆柱、曲线；
- `surface3d`：`z=f(x,y)` 采样网格。

对比型内容第一版用文字/表格，不单独做图。

### 7.2 统一结构

```json
{
  "type": "relation",
  "title": "可选标题",
  "nodes": [{"id":"a","label":"概念","kind":"concept"}],
  "edges": [{"from":"a","to":"b","label":"推出","kind":"arrow"}],
  "shapes": [
    {"kind":"point","x":1,"y":2,"label":"A"},
    {"kind":"segment","from":[0,0],"to":[2,1]},
    {"kind":"curve","expr":"x^2","domain":[-2,2]}
  ],
  "annotations": [{"x":1,"y":2,"text":"关键点"}],
  "view": {"x":0,"y":0,"zoom":1}
}
```

3D 使用同样的节点/形状/标注思路，增加 `z` 与三维原语。模型不得输出任意脚本。

### 7.3 内联标记

模型只在正文中输出短标记（用户不可见）：

```text
[[MG_DIAGRAM:type=relation]]
```

后端职责：

1. 从正文流中剥离标记；
2. 生成 `anchorId`，记录标记在消息中的位置；
3. 启动图解规划；
4. 通过 SSE 发送：

```json
{
  "mg_event": "diagram",
  "requestId": "...",
  "anchorId": "...",
  "diagram": { "...": "结构化图解" }
}
```

5. 同一 `requestId + anchorId` 只执行一次。

前端职责：

1. 遇到标记位置先渲染一个不可见占位；
2. 图解事件到达后填入；
3. 图解未到时正文继续显示；
4. 失败时移除占位，不显示错误块。

### 7.4 规划输入

图解规划器读取：

- 用户本次问题；
- 标记之前的回答正文（最多 6000 字）；
- 当前论文/知识库引用片段；
- 允许的图类型与数量上限。

规划器输出结构化图解；前端不调用模型。

## 8. 渲染

### 8.1 2D

- 用 SVG 渲染；
- 支持鼠标/触控拖动、滚轮/双指缩放、重置视图；
- 不自动动画；
- 文字、节点、边、坐标统一主题变量；
- 大图按视口裁剪，节点/边数量受限。

### 8.2 3D

- 用 Three.js 静态场景；
- 支持拖动旋转、滚轮/双指缩放；
- 只在交互时重绘，不做持续动画循环；
- DPR 上限 2；
- 离开消息/切换会话时释放几何体、材质、渲染器；
- 移动端可降级为固定视角 2D 投影并提示。

### 8.3 论文脑图

- 从缓存的 `PaperStructure` 生成 `tree`；
- 根节点为论文标题，一级为研究问题/方法/结论/局限/章节；
- 支持折叠、展开、拖动、缩放；
- 节点若有页码锚点，点击跳回阅读器对应页；没有则不跳；
- 不重新调用模型。

## 9. 存储

- `ChatMsg` 增加 `diagrams?: DiagramBlock[]`；
- 学习区与科研主聊天随现有会话 localStorage 保存与恢复；
- 论文工作台左栏聊天保持“关闭即清空”，图解不落库、不恢复；
- 单条消息最多 2 张图；
- 单图节点 ≤40、边 ≤80、2D 形状 ≤100、3D 网格 ≤60×60；
- 清理消息/会话时图解一起删除；
- 不写入 `doc_insights`，不进入论文结构缓存。

## 10. 安全与降级

- 图解 schema 白名单校验；未知类型/字段丢弃；
- 文本转义，禁止 HTML/JS；
- 坐标、节点数量、曲线采样点设上限；
- 3D 不加载外部模型/贴图；
- 规划超时（如 12s）则放弃该图；
- 渲染失败只显示文字，不阻塞回答；
- 图解事件跨消息/跨论文不串用。

## 11. 验收

1. 论文脑图从缓存打开，重复打开不调用模型；
2. 论文脑图可折叠、拖动、缩放；
3. 回答中模型标记位置出现图解，正文不中断；
4. 回答图解刷新页面后仍在；删除消息后消失；
5. 回答图解不出现在论文结构缓存；
6. 2D 可拖动/缩放；3D 可旋转/缩放；无自动动画；
7. 寒暄和简单回答不生成图；
8. 图解失败不影响回答；
9. 学习区/科研区隔离不变；
10. 后端测试、前端测试、类型检查、构建通过。

## 12. 实施顺序

1. 图解 schema + 2D SVG 渲染器 + 论文树；
2. 回答标记、SSE `diagram` 事件、消息持久化；
3. relation/flow/geometry2d/plot2d 规划器；
4. 3D Three.js 渲染器与 geometry3d/surface3d；
5. 手动“图解此段”与理解型兜底；
6. 移动端与性能上限；
7. 回归测试与发布。
