# 表示形式契约

日期：2026-11-02
适用范围：图解、检索、批注、文档生成等所有“系统替用户选择表现形式”的功能。

## 1. 要防止的现象

系统有一个最省力的默认表示（图解里是关系图/思维导图），模型和代码就把任何输入都塞进这个模板：

- 用户明确要三维曲面，输出仍是关系网；
- 用户要“一步一图”，输出一张冗长的大图；
- 图里坐标、比例、文字位置靠模型手估，不按真实几何计算；
- 用户说“不要思维导图”，模型仍画思维导图。

这类问题的共同点不是提示词写得不好，而是**形式选择没有经过意图和内容的校验，继承了默认值**。

## 2. 普适规律

> **默认表示劫持（Default-Representation Capture）**：任何生成物的形式，必须由“用户显式意图 + 内容结构”共同决定；默认模板只能在没有意图时兜底，而且必须通过机器校验，不能只靠提示词。

## 3. 三条硬约束

1. **显式意图优先**
   - 用户说三维就画三维，说图就画图，说一步步就一步一图。
   - 用户明确要求优先于模型自选类型；多步骤混排时保留每一步自己的类型，不整题覆盖。
2. **内容匹配**
   - 关系网才用 `relation`，层级才用 `tree`；
   - 一元函数及其导数用 `plot2d`（2D）；多元函数、偏导数、曲面、梯度用 `surface3d`（3D）；空间对象用 `geometry3d`；平面几何用 `geometry2d`；
   - 用户没有指定维度时，按“一元/多元、是否含空间对象、是否含曲面/曲线”等关键词权重判断，不默认 2D；
   - 推导步骤/因果链用 `flow`；
   - 抽象概念先找具体类比物，再按表现力选 2D/3D。
   - 张数由内容决定：有明确步骤就按步骤逐张；没有步骤时，按段落关键词 + 全文主题词做权重扫描，超过阈值才画。不要用固定张数代替内容判断。
3. **机械校验**
   - 输出类型必须等于请求类型；
   - 类型与结构必须自洽：节点型必须有 `nodes`，几何型必须有 `shapes`；
   - 错类型、空结构宁可不画，也不能画错形式；
   - 精度由计算保证：表达式服务端采样、梯度数值求导、坐标等比例映射，不信任模型手估。
4. **决策过程不可见**
   - 权重、评分、维度判断、选型依据只在后台使用；
   - 不进入 SSE、会话存储、图题、标签、标注或回答正文；
   - 用户只看到图和内容讲解，不看到“为什么选这种图”。

## 4. 预防清单

新增“生成某种形式”的功能时，按顺序落地：

1. 入口解析用户显式形式意图（类型、数量、节奏）。
2. 规划器输出必须带类型；缺类型时用请求类型补齐。
3. 校验器检查类型、结构、数量、坐标范围与精度；不接受“schema 合法但类型/结构不符”。
4. 规划失败或类型不符时降级为“不生成”，并保留文字回答；不要用默认模板顶上。
5. 把用户每次“不是这个”的纠正写成回归测试；同类问题不得二次发生。

## 5. 当前落点

- `backend/research_diagrams.py`
  - `explicit_types()` / `explicit_type()`：显式意图优先，多类型混排不覆盖；
  - `validate_diagram()`：类型-结构自洽校验；
  - `plan_diagram()`：请求类型一致性校验，错类型返回 `None`；
  - `_sample_shape()` / `_refine_gradient()`：表达式采样与梯度数值求导。
- `frontend/src/utils/diagramSpec.ts`
  - `parseDiagramSpec()`：同样的类型-结构校验；
  - 几何图等比例映射到像素坐标，避免字号/比例失真。
- `backend/chat.py`
  - 图解提示词：边讲边画、一步一图、类型匹配、抽象概念先类比。

## 6. 推广

同一规律适用于：

- 检索：用户要“在右栏打开”时，不能默认跳外部网站；
- 批注：用户要“框住这一段”时，不能默认整页框选；
- 文档生成：用户要“按这个结构”时，不能默认套模板；
- 任何有默认输出形态的模块：先解析意图，再校验形式，最后才生成。
